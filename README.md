# 투자 의사결정 스크리너 MVP

기업의 질, 가격, 기술적 타이밍을 분리해 보여주는 한국 상장기업 비교 스크리너입니다.

## 주요 기능

- 기업 비교: DART 재무 원자료, 금융위원회 주가, 업종 비교, 사용자 투자 조건
- 주가 차트: 기본 5·20·60·120일 이동평균선과 사용자 지정 기간 저장
- 시장 정보: 최근 1·3·6개월·1년 가격수익률, DART 현금배당수익률·주당배당금
- 기업 집중분석: 한 종목의 5개년 재무와 최근 주가 흐름
- DART 공시: 별도 페이지에서 공시 목록 조회 및 원문 연결
- 리서치: 저작권을 지키는 원문 링크 허브
- 백테스트: 최대 5개 종목의 2020년 이후 사용자 지정 기간 가격수익률·MDD·변동성
- ETF 비교: 최대 6개 ETF의 KRX 최신 시장지표와 1·3·5년·최대 가격수익률 비교
- 금융업·지주사: 비교 적합성과 무관하게 발표된 DART 수치는 숨기지 않고 표시
- 설치형 웹앱: 공개 URL을 PC·모바일에 FinScope 앱으로 설치하고 CMD 없이 실행

## 설치형 앱

배포된 FinScope 주소를 Chrome 또는 Edge에서 열고 상단의 **앱으로 설치**를 누르면 바탕화면과 시작 메뉴에서 바로 실행할 수 있습니다. 앱으로 설치한 뒤에는 PC를 재부팅해도 로컬 서버나 `START_LOCAL.cmd`를 실행할 필요가 없습니다. 최신 금융 데이터 조회에는 인터넷 연결이 필요합니다.

## 실행

```powershell
cd investment-platform\current
node server.mjs
```

브라우저에서 `http://localhost:4173`을 엽니다.

Windows에서는 `START_LOCAL.cmd`를 더블클릭해 실행할 수도 있습니다. 세부 검증 순서는 [`LOCAL_TEST.md`](LOCAL_TEST.md)를 참고하세요.

서버는 우선 현재 폴더의 `.env`를 읽고, 없으면 기존 `../stock/.env` 설정을 사용합니다. 인증키는 브라우저로 전달되지 않습니다.

## MVP 기능

- DART 상장기업 검색 및 최대 10개 기업 선택
- 사업보고서(연간·4분기 포함)·1분기·반기·3분기 연결재무제표와 동일 기간 5개년 추이
- 매출, 영업이익, 영업이익률, ROE, 부채비율, FCF 비교
- 금융위원회 API 기반 현재가·시가총액 및 이동평균선
- 표, 추이 차트, CSV 다운로드
- 그래프 포인트 호버 시 연도별 실제 수치 표시
- 지표·연산자·기준값을 조합한 사용자 조건식과 로컬 저장

## 매크로 데이터 API

- `GET /api/macro/catalog`: 지원 지표와 설정 상태
- `GET /api/macro/series?id=kr-base-rate&beginDate=20210101&endDate=20261006`: 표준 시계열과 품질 정보
- `GET /api/macro/snapshot`: ECOS·FRED·EXIM 최신 묶음
- `GET /api/macro/exchange`: 수출입은행 환율
- `GET /api/macro/loan-rates`: 수출입은행 대출금리
- `GET /api/macro/international-rates`: SOFR·ESTR·EURIBOR 등 중첩 응답 표준화
- `GET /api/macro/export.csv?id=us-10y`: 출처·상태·결측 사유를 포함한 CSV

승인된 KRX API도 같은 표준 시계열 형식으로 제공합니다. KRX 산업지수, 석유시장 휘발유·경유, 배출권 KAU, 주요 선물(코스피200·미국달러·3년국채·반도체·에너지화학), ESG Leaders·기후변화지수를 월별 마지막 거래일 값으로 정렬합니다. 화면에는 원천 일별 빈도와 월별 표본화 방식을 함께 표시합니다.

데이터 연관성 분석에서는 기업 수익률 또는 두 공식 지표를 선택해 피어슨·스피어만 상관계수, OLS 민감도와 R², -6~+6개월 시차, 이동상관, 기간 전반부·후반부 관계 변화를 비교하고 정렬된 원자료를 CSV로 내려받을 수 있습니다.

`/mission.html`은 교육 미션용 금리·환율 산업 스트레스 리포트입니다. ECOS 원/달러·국고채 3년과 금융위원회 일별 지수·주가를 공통 거래일로 맞춰 8개 산업, 업종별 대표기업 3개, 최근 250·375·500거래일을 비교합니다. `GET /api/mission/rate-fx-industry?days=250`에서 원자료를 제공하며 스트레스일은 원/달러와 국고채 3년 금리가 같은 날 모두 상승한 날로 정의합니다.

ECOS는 `list_total_count`를 기준으로 전체 페이지를 수집하고 날짜 중복을 제거합니다. FRED의 `.` 값은 삭제하거나 0으로 바꾸지 않고 `not_published` 결측으로 보존합니다. EXIM 국제금리 중 만기명이 없는 항목은 임의로 이름을 붙이지 않으며 분석 가능 상태에서 제외합니다.

ETF 최신 스냅샷은 KRX 공식 API를 사용합니다. 기간 시세는 금융위원회 ETF API를 먼저 호출하고, 미승인 상태에서는 네이버 공개 일봉을 보조 경로로 사용하되 API 응답과 ETF 화면에 비공식 출처임을 명시합니다.
- 표시할 표 지표 사용자 선택
- KRX 시가총액 상위 종목 및 DART 산업코드 기반 업종 탐색
- 동일 산업 시가총액 상위 5개사의 주요 수익성·안정성 지표 중위값 비교
- 각 지표 설명 툴팁과 데이터 산식 안내
- 퀄리티·가격·기술적 타이밍을 별도 판단
- 금융·보험·금융지원업은 일반기업식 영업이익률·FCF 평가를 제외하고 ROE·순이익·PER·PBR 중심으로 해석
- 금융업이 공시한 영업이익·순이익·이자수익·수수료수익·보험수익을 별도 표에 표시하고 실제 확보된 공시연도 수를 안내
- 최대 10개 선택기업을 데스크톱에서 5개씩 배치하는 와이드 대시보드
- 최근 252거래일 종가와 5·20·60·120·200일 이동평균선 차트 및 기업 전환

수치는 투자 판단 보조용입니다. 업종별 회계 차이와 일회성 항목은 반드시 원문 공시로 재확인해야 합니다.

주가는 금융위원회 일별 주식시세에서 확인되는 가장 최근 확정 종가를 원 단위로 표시합니다. 장중 및 NXT 애프터마켓 시세는 포함하지 않습니다. 분기·반기 손익계산서와 현금흐름표는 누적 금액(`thstrm_add_amount`)을 우선 사용하며 재무상태표는 해당 기말 금액을 사용합니다.

ETF 목록과 최신 정보는 승인된 KRX ETF 일별매매정보를 사용합니다. 기간 시세는 금융위원회 증권상품시세정보를 우선 호출하며, 해당 서비스가 별도 미승인 상태이면 네이버의 공개 일봉 응답을 읽기 전용 보조 경로로 사용합니다. ETF 백테스트는 가격수익률이며 분배금 재투자를 포함하지 않습니다. 네이버 리서치 목록 또한 공식 공개 API가 아닌 공개 페이지 내부 응답이므로 구조 변경 시 원문 검색 링크만 제공될 수 있습니다.

## 배포

Node.js 서버를 배포하고 API 키를 호스팅 서비스의 Secrets로 등록해야 합니다. 기업 검색 데이터는 `data/companies.json`에 포함되며 `npm run build:data`로 기존 DART 기업코드 캐시에서 갱신합니다.

비공개 GitHub 저장소와 Koyeb을 이용하는 순서는 [`DEPLOYMENT_KOYEB.md`](DEPLOYMENT_KOYEB.md), Render 대안은 [`DEPLOYMENT.md`](DEPLOYMENT.md)를 참고하세요. 공개 운영을 위해 API 키 서버 보관, 6시간 메모리 캐시, 사용자별 분당 60회 요청 제한, 보안 헤더, 데이터 기준일과 투자 비권유 고지문을 적용했습니다.

포트폴리오 제출용 운영 방식은 **로컬 HTML 파일이나 PC 시작프로그램이 아니라 공개 서버 URL**을 권장합니다. ECOS·FRED·KRX·DART 인증키를 브라우저 파일에 넣으면 노출되므로, 현재처럼 Node 서버에서 키를 보관한 뒤 공개 URL을 공유해야 합니다. 이 주소에서 FinScope PWA를 설치하면 재부팅 후에도 CMD 실행 없이 일반 앱처럼 열 수 있습니다.

개인·교육용 배포와 별개로 공개 또는 수익화 서비스는 KRX 및 금융위원회 데이터의 이용 조건을 별도로 확인해야 합니다. 현재 KRX OPEN API 약관은 비상업적 이용을 원칙으로 하고 있으므로 상업 서비스 전에는 KRX 데이터사업부와 데이터 이용·재배포 권한을 협의해야 합니다. API 일일 호출량을 고려해 운영 환경에서는 영속 캐시와 사용자별 요청 제한도 추가하는 것이 안전합니다.
